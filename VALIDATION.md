# Validation boundary

## Editorial format

See `EDITORIAL_STANDARD.md` for field definitions, source classification and wording policy. Team-proposed review records and roles are kept separate from documented product behavior.

## Evidence

Original capability audits are retained as 20 October 2026 snapshots. The source-linked presentation material and this narrative revision are dated 21 October 2026. Selected availability, execution and authorization boundaries were rechecked against official AWS and Kiro documentation; this is not a new claim-by-claim audit of every URL.

## Build checks

The build checks local paths and anchors, unique HTML IDs, narrative completeness, all five presentation and demonstration budgets, presentation reference IDs, all 83 appendix records, neutral wording in authored titles/takeaways, and PowerPoint existence. `qa/build-validation.json` records the structural results. Browser checks, when available, are recorded separately in `qa/browser-validation.json`; absence of that file does not imply they passed.

## Not tested

No live AWS accounts, repositories, deployments, agent runs, penetration tests or purchasing workflows were exercised. Demonstration budgets include prepared-result fallback paths and are not agent-runtime guarantees. The cost fixture is synthetic. No measured reliability, accuracy, security-detection, productivity or savings outcomes are claimed.

## Publication

Repository visibility and hosting settings are not changed by the build. The generated HTML works locally. Publishing files to GitHub does not automatically enable GitHub Pages. Historical audits, code revisions and unrelated files remain intact.


## Mechanisms extension

See [the mechanism-specific validation boundary](mechanisms/VALIDATION.md) and `qa/mechanism-validation.json`. This extension uses a new official-documentation review, with explicit source discrepancies, and does not claim a new audit of every earlier report statement.
