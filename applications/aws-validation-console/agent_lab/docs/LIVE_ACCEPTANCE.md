# Live acceptance: not yet executed

The release is **0.3.0-rc1**, not a validated result about your Agent Space. Local tests prove software paths under stated fixtures and a real loopback workload; they do not prove account authorization, FIS efficacy, agent response, diagnosis quality or prevention on AWS.

The design's 30 requirements are retained in `validation/acceptance-traceability.json` with separate implementation, local evidence and live status. Do not interpret a successful mocked test as closure of its live gate.

## First authorized response acceptance

Select one reversible failure on an actual non-production deployment in account B. An administrator supplies actual account IDs, Agent Space/association, profiles, approved explicit targets, finite template, real native incident-reference contract, alarm, independent verifier reads, business-path probe, service-owned limits, safety controls and cleanup. Verify IAM, network reachability and credential refresh independently.

Start with writes disabled. Open the empty console, register a real experiment, qualify it, and inspect all identity/source records. A failed identity, changed template or missing alarm must block execution. Prove the emergency stop/cleanup independently. Only then enable writes and approve the displayed exact account/target/action subject.

Run a real baseline and one approved exposure. Retain actual request measurements, fault effect and resolved targets, real alarm transition, sender acceptance/rejection, correlated native task, execution/journal records, proposed intervention, actual cleanup and finalized assessment. Do not type a task ID or invented measurement to fill a gap. A native-trigger failure must not be rescued with assisted task creation.

Adjudicate diagnosis against the captured fault evidence using the frozen rubric and source quotations. If an agent-linked intervention is approved, retain the exact Automation execution and verified changed state. Separate this actor from the agent. Recovery following a change remains an association without a qualified counterfactual; no automatic causal credit is issued.

## First prevention acceptance

Register the comparison and history limitations before baseline. Obtain a qualified baseline incident. Approve an actual agent EVALUATION; retrieve and pin a real recommendation version with its task lineage. Map it to a reviewed deployment/runbook change, not arbitrary prose. Execute only after exact approval. Verify actual deployed state using independent reads.

Repeat the same qualified exposure and workload after the change. Verify the change before and after replay. Match target set, actual fault duration, traffic, experiment revision and collection completeness. Preserve failures, aborted attempts and unmatched trials. For earlier investigation, run a qualified post-change benign control as well. A before/after pair demonstrates only the declared measured claim under its recorded conditions, not general prevention competence.

## Recovery and failure acceptance

Test separately: worker loss after submission, unknown write outcome, expired approval, changed template/runbook, incident delivery rejection, no task after confirmed delivery, denied/partial collection, no offered traffic, failed cleanup and abort during an intervention. Cloud-side stopping must remain usable when the local process is unavailable. Do not deliberately remove your only recovery path.

No production release or general agent-competence claim is authorized by the supplied local validation record.
