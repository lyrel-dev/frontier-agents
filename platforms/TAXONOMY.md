# Platform-reference classification

## Platform capability

A reusable ability exposed by the platform.

Example: Retain operational context across investigations.

## Operation

An action on a platform resource or configuration object.

Example: Attach a memory store or change its active state.

## Mechanism

The documented process connecting inputs, state, execution and outputs.

Example: Select a store by description, then retrieve relevant entries.

## Use case

An engineering problem that combines capabilities and mechanisms.

Example: Investigate a recurring alarm while checking contradictory telemetry.

## Record requirements

Capabilities must identify reusable ability, resource, operation, scope and boundary. Mechanisms must identify trigger, process, retained state, enablement, controls and observable verification. Use cases reference those records instead of duplicating them. Do not infer model training, shared memory, vector databases or a universal approval system from product positioning.

## Publication scope

The new platform layer is the authority for this classification. Existing timed scenario presentations are retained separately and were not rebuilt as part of this layer. No historical snapshot directories or distribution archives are created.
