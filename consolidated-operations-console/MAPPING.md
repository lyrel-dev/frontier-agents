# Source model consolidation map

**Source baseline:** `main` at [`d926a81`](https://github.com/lyrel-dev/frontier-agents/tree/d926a81c584b6b69f41bfb9641532c4f8f2d7cb3). Only tracked work under `aws/<service>/analysis` at this commit is mapped. The complete file inventory is in [INVENTORY.md](INVENTORY.md).

This crosswalk preserves every named concept in the source entity diagrams, the report-only supporting concepts, and the selected native value shapes. It deliberately distinguishes independently identified entities, owned values, derived projections, retained provider DTOs, and future provider commands. A named SDK shape is not automatically a new lifecycle root. The machine-readable equivalent and provider-family register are in [adapter-profiles.json](model/adapter-profiles.json).

## Representation rules

| Disposition | Meaning |
|---|---|
| `canonicalEntity` | One or more of the 37 consolidated entities owns identity/lifecycle. Owned children still need no independent CRUD operations. |
| `ownedValue` | Typed value, reference, association, result, history entry or snapshot member belongs to a canonical owner. Its local key and invariants remain explicit. |
| `projectionProfile` | One of the five typed immutable `ProjectionRevision` variants with exact sources and derivation: `EVALUATION`, `LIFECYCLE_EXPOSURE`, `INVESTIGATION_RESULT`, `SERVICE_STATUS`, `WORKSPACE_SUMMARY`. |
| `retainedAdapterDto` | Explicitly named provider or previous application payload retained as a typed `SourceRevision` profile. It is inspectable as captured evidence; dedicated management/UI normalization is deferred. |
| Deferred native mutation | Listed on the profile, not a writable property copied from a read DTO. It requires a future authorized adapter and outcome reconciliation. |

All canonical entities have `workspaceId` and an opaque local ID. Native IDs/ARNs remain qualified values, aliases and provenance. `SourceIdentity` carries the owning provider tuple and service-specific parent scope; a second Connection or a changed role does not create a second native resource. Module current fields refer to immutable evidence/projection revisions; retained source payloads and history are never rewritten by a later parser or local edit.

The registry binds `SourceRevision.profile` to its full `profileId` (for example `aws.health.event/v1`) with `profileVersion: "1"`. Only an explicit `normalizedBinding` declares a current schema shape or one of the five projection enums. Rich prior timeline/assertion/action renditions remain typed application-origin `LOCAL_EVIDENCE` source captures with provenance; the initial schema does not pretend to expose an undeclared normalized projection. Graph nodes and edges are owned `Snapshot.contents` values through `GraphContents`.

## Canonical entity budget

| Module | Entities |
|---|---|
| foundation | `Workspace`, `Connection`, `Resource`, `Collection`, `ReadAttempt`, `SourceRevision`, `Observation`, `ProjectionRevision`, `Snapshot`, `WorkItem`, `Command` |
| workload | `System`, `UserJourney`, `Service`, `Dependency` |
| health | `HealthEvent`, `EventContext`, `EntityImpact`, `Communication`, `LifecycleEntry`, `ComponentDeployment` |
| resilience | `ResiliencePolicy`, `ResilienceAssessment`, `Finding`, `Recommendation` |
| investigation | `AgentSpace`, `Investigation`, `Execution`, `JournalRecord`, `ApprovalRequest`, `Asset` |
| workflow | `Scenario`, `ScenarioRevision`, `Run`, `StepRun`, `StepAttempt` |

These 37 entities are the complete phase-1 class-model budget. Provider wrapper shapes, catalog parameters, graph edges, policy components, communication pages, snapshot membership, work actions and source identities remain typed owned values or profiles. The initial package does not introduce a general-purpose entity/attribute database or a CRUD API for each schema name.

## Deliberate changes at the consolidation boundary

1. **One evidence spine.** The workflow `Evidence` root, Health source history, Resilience observations and DevOps retained revisions converge on `SourceRevision` (what was retained) and `Observation` (when/how it was seen). `Collection` and `ReadAttempt` preserve attempted, empty and failed reads. A Run owns exact evidence-reference/import records with producer and authorization provenance; source revision reuse cannot bypass run scope.

2. **Local workload catalog.** `System`, `UserJourney`, `Service` and `Dependency` provide console identity, metadata and membership. Native Resilience bindings and configuration remain observed facets. A console `UpdateService` edits local catalog state; it does not send native `UpdateService`, rename an AWS resource, change permissions or reconfigure discovery. Any later native command must say so explicitly.

3. **Three execution domains.** Console `Run`, FIS `Experiment` and native `ResilienceAssessment` keep distinct lifecycles. DevOps `Investigation`/`Execution` also retain their provider meanings. A qualified external-operation reference connects them only when evidence establishes the relationship.

4. **No accidental name equivalence.** A provider `AgentSpace` is not a console `Workspace`; a DevOps `RegisteredService` is not a business `Service`; monitoring health is not an AWS `HealthEvent`; DevOps published findings are assertion projections rather than native Resilience `Finding` identities. Native goal/trigger/prevention management remains a named adapter scope.

5. **Reassessment retains history.** Reinterpreting an experiment or workflow with new evidence, cutoff or evaluator publishes a new immutable `EVALUATION` ProjectionRevision over a frozen input Snapshot. It does not reopen a sealed result or pretend the provider reran. A read-only Run may orchestrate evaluation when needed, but is not required. This is a deliberate extension to the source workflow v0.2 proposal, which deferred a separate reassessment lifecycle; it adds no new entity.

6. **Snapshots freeze evidence and uncertainty.** Snapshot manifests pin source/projection revisions, read attempts and the coverage values used at capture. Mutable Collection or latest-result pointers cannot change earlier captures. Snapshot access still observes current authorization/retention; a technical current-refresh failure only makes comparison unavailable.

## Peripheral provider families and future commands

A retained adapter DTO is a declared integration boundary, not a promise that the initial console implements all native capabilities. The profile registry names the identity, known field types, source shapes, read path and reason for deferring each mutation. Captured original payloads remain available when a module cannot yet interpret them. Unknown future provider members/types remain preserved and explicitly unsupported in normalized views.

| Family | Retained model | Deferred execution or management |
|---|---|---|
| Health organization aggregation | Integration-state profile on Connection evidence | Enable/disable plus readiness and backfill reconciliation. No native event acknowledgement/close is invented. |
| DevOps integration registration and associations | `RegisteredService`, `Association`, typed configuration, webhook descriptors | Native onboarding, validation, role/network/credential-bearing association changes. |
| DevOps chat and directed actions | Chat/stream DTOs, `ApprovalRequest`, separate decision/resume `Command` audit | Sending messages, approval submission/resumption and ambiguous-response recovery. No invented approval read/revoke API. |
| DevOps goals, recommendations and triggers | Explicit typed prevention/automation DTOs with their own native keys, state, task/goal links and open content | Goal/recommendation lifecycle and native scheduling/automation management; no identity merge with Scenario or Resilience suggested changes. |
| DevOps provider operator app/private network | Access/IdP/private-connection descriptors | Provider app enablement, IdP updates, network provisioning and certificate rotation. |
| DevOps asset profiles and usage | Native asset type/version/file profiles and account usage-window DTOs | Upload/mutate/delete asset content; usage remains observation. |
| FIS catalogs/templates/target accounts/safety lever | Catalog and template DTOs, captured account settings and scoped safety state | Template/configuration/safety-control changes, experiment dispatch and stop. No independent action stop/retry/pause. |
| Resilience native catalog/configuration | Qualified native system/journey/service/policy aliases and observed payloads | Live provisioning, sharing, permissions, discovery, policy and input-source writes; local catalog commands retain local ownership. |
| Resilience assessments/findings/dependencies | Native typed evidence behind canonical module entities | Assessment start and native finding disposition/dependency criticality edits. Local completion/governance cannot substitute for provider commands. |
| Resilience input-source/function/resource context | Explicit input-source unions, service-local resources and function references | Full service-function authoring and provider discovery configuration; these need the separately pinned SDK contract before use. |
| Monitoring and query adapters | Typed alarm/metric/logs envelopes with exact native source and coverage | Query dispatch/collection, timing and source-specific claim-sufficiency evaluation. A generic success response cannot establish passed criteria. |

The source Resilience package contains a local 44-operation RPC mock; the source workflow package contains 16 operation contracts/reference validators; DevOps includes a 63-operation native inventory; Health includes its 15-operation native inventory. Those counts describe different surfaces. The new API is a console contract with its own namespace and cannot be inferred to implement every original native operation. Existing source operation inventories remain the detailed authority for provider translation.

## Lossless migration and acceptance

Import source identities and revisions first, then explicit canonical bindings, owned associations, collection evidence and derived profiles. A migration preserves raw payload, original field presence, timestamps, enum strings, correlation basis and every retained historical revision. Record unresolved identities as unresolved; never auto-merge by name or silently assign a resource to an account, task, assessment or snapshot.

Before accepting an adapter, round-trip the source fixture through its retained profile and compare identity sets, association sets, count units and evidence references. Exercise duplicates, equal-time conflicts, partial/failed pages, missing versus null/zero/empty, unknown output values, independent workflow/provider states, exact result pointers, and immutable snapshot coverage. These are semantic acceptance gates; a JSON parse or matching class count alone is insufficient.

The mapping is intentionally independent of a physical database layout. Arrays of small owned values may later become indexed child tables without changing their logical ownership, scope, version rules or public identity. New modules should first reuse the evidence/reference/snapshot contracts; add a new entity only when it has a distinct identity and lifecycle that existing typed values cannot express.
