Use cases/Findings and repair

AWS Security Agent

Revalidate a finding after deployment of a repair

Determine whether a selected issue still reproduces under valid current test conditions.

Responsible actor. Verification owner

1. Purpose and scope

The reviewed repair has been deployed to the original authorized environment. Select the existing finding for revalidation and inspect the new job, including the current authentication configuration and target revision. The job repeats the selected validation steps rather than conducting a broad new assessment.

Interpret the result within that scope. A reproduced finding remains active evidence of the issue; non-reproduction supports resolution only when the relevant identity and path were actually reached. Keep the original finding and the linked job history. A failed login or changed test environment must not be mistaken for a successful repair.

Inputs
Completed original finding, deployed repair and current authentication configuration.
Expected output
Separate revalidation job linked to the original finding with Active or Resolved result.
Execution pattern
On demand
Delivery mode
Native operation

2. Workflow

The workflow order, acceptance criteria and failure decisions are authored engineering guidance. Each mechanism links to documented service behavior and concrete configuration features.

  1. Confirm deployed repair and target

    Match the finding, source change and actual deployed revision.

    Responsible actor. Responsible engineer or reviewer

    Dependency. Required. Applies to the selected implementation.

    Implementation. Engineering procedure; no native service operation is asserted for this step.

    Effect. Team decision; no implicit service action

    Verification. Record the decision with the source identifiers and evidence needed for the case completion criteria.

    Failure handling. Keep the result unresolved and assign the missing decision or evidence to an owner.

  2. Check current test authentication

    Avoid interpreting an inaccessible path as repair.

    Responsible actor. Service execution; accountable engineer reviews the result

    Dependency. Conditional. The selected finding requires authenticated access.

    Platform process. Credential resolution and application login. Obtain the test credential and apply it to the application.

    Configuration. Test credentials and preflight

    Effect. Authentication requests

    Verification. Check the actual application identity and protected route, not only credential retrieval.

    Failure handling. Mark protected paths unassessed when login fails.

  3. Run selected revalidation

    Retest the original finding and preserve its lineage.

    Responsible actor. Service execution; accountable engineer reviews the result

    Dependency. Required. Applies to the selected implementation.

    Platform process. Selected finding replay and lineage. Repeat selected finding-validation steps under current test conditions.

    Configuration. Finding revalidation jobs

    Effect. Targeted active test

    Verification. Verify reached identity, deployed repair and linked result.

    Failure handling. Record authentication or environment failure as inconclusive verification.

Setup procedure

  1. Review the saved scope before starting execution.
  2. Test target reachability and actual application identity.
  3. Start a separate run and retain excluded or incomplete paths.
  4. For revalidation, confirm the deployed repair and select original findings rather than run broad discovery.

Proposed checks

  • Failed authentication leaves protected paths unassessed.
  • Each run identifies the actual target revision and roles.
  • Revalidation retains the original finding and separate job.

Stop behavior. Stop unexpected effects. Control future schedules separately from current jobs, findings and external tickets.

Supporting procedures for this configuration

This recipe is reused by multiple workflows. The required, optional, or conditional dependencies for this use case are specified in its workflow above.

  • Application-context assembly
  • Target scope and network access
  • Credential resolution and application login
  • Successful login-procedure reuse
  • Saved assessment and independent execution
  • Selected finding replay and lineage

4. Verification and limits

Completion criteria

  • The intended repair is deployed to the target.
  • The relevant identity and path were reached.
  • The linked job records reproduction, non-reproduction or an inconclusive result.

Prerequisites and availability

GA penetration testing

Limitations

Revalidation does not rediscover unrelated vulnerabilities or establish whole-application security.

Example request

Revalidate the selected finding against the deployed revision and record the actual test identity.

Verification procedures are proposed checks. This documentation does not report a live execution of the workflow.
