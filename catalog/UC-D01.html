AWS DevOps Agent

Triage incident signals

Route a signal to the appropriate investigation or justified exclusion.

Responsible actor. On-call engineer

1. Purpose and scope

An on-call engineer receives several alerts for the same service. Before opening another investigation, the engineer needs to know whether the new signal belongs to work already in progress. Inspect the triage decision and its reason, then follow the primary investigation when the signal was linked. A skipped signal should identify the matching exclusion rather than disappear from the operating record.

When correlation is wrong, unlink the signal so it can be investigated separately. When a skip criterion excluded a relevant event, review that criterion and use the supported unskip operation. The result of this use case is correct routing and an identifiable investigation, not a root-cause conclusion. Root-cause analysis follows in the next use case.

Inputs
Incident identity, correlation evidence, skip criteria and active investigations.
Expected output
Triage decision, reason and resulting investigation linkage.
Execution pattern
Event-driven
Delivery mode
Built-in function

2. Workflow

The workflow order, acceptance criteria and failure decisions are authored engineering guidance. Each mechanism links to documented service behavior and concrete configuration features.

  1. Inspect routing

    Determine whether this signal requires independent work.

    Responsible actor. Service execution; accountable engineer reviews the result

    Dependency. Required. Applies to the selected implementation.

    Platform process. Incident routing. Link the signal, skip it under configured criteria or proceed with independent investigation.

    Configuration. Incident triage and investigations

    Effect. Investigation linkage

    Verification. Inspect the routing decision, reason and resulting investigation identity.

    Failure handling. Correct routing through the supported unlink or unskip operation.

Setup procedure

  1. Verify operator access independently from resource and tool access.
  2. For incident work, start from a signal or scoped manual investigation. For prevention work, inspect a manual or scheduled evaluation over existing investigation evidence.
  3. Inspect triage, current evidence and any observable historical-context retrieval separately.

Proposed checks

  • Current observations contradict a prior cause: the conclusion must follow current evidence.
  • A missing source produces an explicit evidence gap.
  • Correcting routing changes linkage, not production resource state.

Stop behavior. Use supported investigation controls. Steering and feedback do not grant mutation authority.

4. Verification and limits

Completion criteria

  • Decision and reason are visible.
  • The resulting investigation or exclusion is identifiable.

Prerequisites and availability

GA production operations

Limitations

A triage decision is not a diagnosis. Incorrect linking or skipping requires a routing correction.

Example request

Explain why this alert was linked, skipped or scheduled for a new investigation.

Verification procedures are proposed checks. This documentation does not report a live execution of the workflow.
