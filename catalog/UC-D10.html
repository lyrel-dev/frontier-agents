AWS DevOps Agent

Consolidate and maintain operational procedures

Maintain one reviewed procedure for the intended operational situation.

Responsible actor. Runbook owner

1. Purpose and scope

A team has several overlapping timeout SOPs maintained by different owners. First reconcile their scope, resolve contradictory steps, remove stale tool names, and identify the approved procedure. Only then package that procedure as a skill with a description that states when it applies and which agent types may use it.

Keep the reviewed source in Git and test a request that should match the skill alongside one that should not. The supporting references should explain the expected observations and the point at which the procedure stops or escalates. Consolidation is authored team work; skill selection is the platform mechanism. A skill neither creates the referenced tools nor grants permission to use them.

Inputs
Reviewed SOP, target agent types, actual tool names and expected evidence.
Expected output
Version-controlled SKILL.md bundle and a matching/nonmatching selection test.
Execution pattern
On demand
Delivery mode
Composed workflow

2. Workflow

The workflow order, acceptance criteria and failure decisions are authored engineering guidance. Each mechanism links to documented service behavior and concrete configuration features.

  1. Reconcile authoritative procedures

    Resolve conflicting scope, stale commands and ownership before packaging.

    Responsible actor. Responsible engineer or reviewer

    Dependency. Required. Applies to the selected implementation.

    Implementation. Engineering procedure; no native service operation is asserted for this step.

    Effect. Team decision; no implicit service action

    Verification. Record the decision with the source identifiers and evidence needed for the case completion criteria.

    Failure handling. Keep the result unresolved and assign the missing decision or evidence to an owner.

  2. Publish and test the procedural skill

    Make the reviewed procedure available to the intended agent scope.

    Responsible actor. Service execution; accountable engineer reviews the result

    Dependency. Required. Applies to the selected implementation.

    Platform process. Runbook applicability and procedural loading. Make the reviewed procedure and its references available to the intended execution.

    Configuration. Skills and supporting references

    Effect. Procedural context

    Verification. Test matching and nonmatching requests and inspect exposed procedure or tool-use evidence.

    Failure handling. Correct applicability or missing tools; stop unsupported steps without implicitly widening permissions.

Setup procedure

  1. Reconcile conflicting SOPs and obtain an accountable review.
  2. Package the approved procedure as a skill with its applicability description.
  3. Keep broadly applicable reporting conventions in standing instructions only where appropriate.
  4. Test a matching and a nonmatching request using non-sensitive evidence.

Proposed checks

  • Irrelevant tasks do not require the skill.
  • Required tools exist and unsupported steps stop explicitly.
  • Changes to standing instructions are tested in a new applicable session.

Stop behavior. Deactivate or revise the relevant procedural configuration using the supported controls. Changing a skill does not undo past actions or grant new access.

4. Verification and limits

Completion criteria

  • Conflicting or stale instructions are resolved.
  • Actual tools and stop conditions are defined.
  • Applicability tests include matching and nonmatching requests.

Prerequisites and availability

GA skills

Limitations

Consolidation and review are team work. A skill supplies procedure; it does not grant tools or permissions.

Example request

Create a skill from the approved checkout timeout SOP and state when it should and should not load.

Verification procedures are proposed checks. This documentation does not report a live execution of the workflow.
