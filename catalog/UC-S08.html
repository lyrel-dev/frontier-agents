AWS Security Agent

Consolidate and maintain security requirements

Maintain reviewed assessment criteria derived from authoritative policy.

Responsible actor. Security policy owner

1. Purpose and scope

Policy owners have revised several overlapping security standards. Reconcile the governing documents and identify the approved source before generating a replacement requirement pack. Compare the generated applicability and compliance statements with that source, including requirements that had previously been added manually.

Regeneration replaces the existing pack contents rather than appending to them. Review the proposed replacement before enabling it for subsequent assessments, and keep the policy and reviewed requirement source in Git. This is a controlled authoring workflow; it must not silently replace a working pack merely because new documents were uploaded.

Inputs
Governed policy sources, existing pack and reviewer.
Expected output
Reviewed replacement requirement pack and external change record.
Execution pattern
On demand
Delivery mode
Composed workflow

2. Workflow

The workflow order, acceptance criteria and failure decisions are authored engineering guidance. Each mechanism links to documented service behavior and concrete configuration features.

  1. Reconcile governing policy

    Identify approved source material and compare existing requirements.

    Responsible actor. Responsible engineer or reviewer

    Dependency. Required. Applies to the selected implementation.

    Implementation. Engineering procedure; no native service operation is asserted for this step.

    Effect. Team decision; no implicit service action

    Verification. Record the decision with the source identifiers and evidence needed for the case completion criteria.

    Failure handling. Keep the result unresolved and assign the missing decision or evidence to an owner.

  2. Generate the replacement pack

    Treat regeneration as replacement rather than append.

    Responsible actor. Service execution; accountable engineer reviews the result

    Dependency. Required. Applies to the selected implementation.

    Platform process. Requirement-pack regeneration. Replace pack contents from the selected policy documents for subsequent review.

    Configuration. Security requirement packs

    Effect. Configuration replacement

    Verification. Compare with approved policy and prior manually added requirements.

    Failure handling. Do not enable an unreviewed replacement; keep authoritative source in Git.

  3. Test requirement applicability

    Check compliant, violating and inapplicable examples.

    Responsible actor. Service execution; accountable engineer reviews the result

    Dependency. Required. Applies to the selected implementation.

    Platform process. Requirement applicability and evaluation. Evaluate supplied evidence against applicable requirements.

    Configuration. Security requirement packs

    Effect. Assessment result

    Verification. Check compliant, violating and inapplicable examples.

    Failure handling. Revise ambiguous applicability; do not treat a pack as a compliance certificate.

3. Configuration

Use the applicable configuration below for the selected workflow. Parameters and checks are engineering guidance, not deployable AWS payloads. Product procedures remain in the linked guide sections.

Setup procedure

  1. Choose the actual mode rather than assume a shared configuration schema.
  2. Connect matching evidence and enable the intended review criteria.
  3. Inspect preflight and completed results separately.
  4. Review repair proposals through ordinary tests and deployment before revalidation.

Proposed checks

  • A new source revision cannot silently reuse stale acceptance.
  • A requirement may be inapplicable rather than compliant.
  • Regenerating a pack is reviewed as replacement.

Stop behavior. Retain unfinished findings. Disable optional writes without discarding their source evidence.

Supporting procedures for this configuration

  • Repository repair proposal
  • Finding publication to Jira

4. Verification and limits

Completion criteria

  • Conflicting policy sources are reconciled.
  • The replacement is compared with prior manual requirements.
  • Applicability and criteria are tested before enablement.

Prerequisites and availability

Preview workflows

Limitations

Regeneration replaces existing requirements, including manual entries. Keep the authoritative source outside the generated pack.

Example request

Regenerate the pack from the approved policy documents and identify which existing requirements would be replaced.

Verification procedures are proposed checks. This documentation does not report a live execution of the workflow.
